# Architecture

## Shape

A single Node process (Fastify) serving both the REST API (`/api/v1`) and the built
React app, backed by one SQLite file in WAL mode. Technicians open a browser on the
LAN. Nothing leaves the machine.

```
browser ── HTTP ──> apps/server (Fastify)
                      ├─ auth: argon2id + opaque session tokens (httpOnly cookie,
                      │        session rows in SQLite — revocable, no JWT)
                      ├─ services: runs, baselines, charts, monitoring, plates,
                      │        csv import/export, reports (print-CSS HTML + SVG)
                      ├─ @sentinel/stats  ← all mathematics lives here
                      └─ @sentinel/db     ← schema, migrations, audit chain
                            └─ data/sentinel.sqlite (WAL, FK on)
```

## Package boundaries

- **packages/stats** — pure TypeScript, zero runtime dependencies. Every routine has
  a docstring with its equation and literature reference, and tests against
  committed fixtures generated once by `tools/reference/generate_fixtures.py`
  (numpy/scipy; Python is never needed at runtime). No math exists anywhere else;
  React components receive numbers, never compute them.
- **packages/db** — drizzle-orm + better-sqlite3. Hand-written SQL migrations
  (applied by a minimal tracked migrator) are the DDL source of truth, including
  CHECK constraints and protective triggers; the drizzle schema mirrors them for
  typed queries. ULID ids, ISO-8601 UTC timestamps.
- **packages/shared** — zod request/response schemas used by server and web.
- **apps/server** — routes validate with zod, enforce roles
  (technician < supervisor < admin), and delegate to services that work directly on
  the SQLite handle inside transactions.
- **apps/web** — React 18, TanStack Router (code-based) + Query, Tailwind. Charts
  are hand-built SVG components using only d3-scale/d3-shape (LJChart, EWMAChart,
  CUSUMChart, ChangePointChart, PlateHeatmap, EffectBars).

## Key invariants

1. **Observations are immutable.** A DB trigger aborts any UPDATE of
   `observation.raw_value/transformed_value/z`. Corrections insert a new observation
   with `supersedes_id`; the original is flagged `superseded` and struck through in
   the UI.
2. **The audit log is append-only and hash-chained.**
   `hash = sha256(prev_hash ‖ canonical_json(row))` from a fixed genesis constant;
   triggers block UPDATE/DELETE; `pnpm verify-audit` walks the chain and exits
   non-zero on any gap, edit, or re-ordering. Logged: run creation, corrections,
   overrides, baseline freezes, config changes, lot changes, report generation,
   logins.
3. **Baselines are frozen objects with effective dates.** Monitoring never drifts
   the reference: a new observation cannot alter an active baseline; re-baselining
   closes the old row (`effective_to`) and inserts a new one.
4. **Rules consume z-scores only.** Transform → z happens once, at entry, against
   the baseline in effect at `performed_at`.

## Build & run

`pnpm build` compiles the packages, builds the web bundle, bundles the server with
esbuild into `dist/server.js` (native modules `better-sqlite3` and `argon2` stay
external, resolved from `node_modules`), and copies the web build to `dist/public`.
`node dist/server.js` serves everything on :8080. Configuration is environment-only:
`SENTINEL_PORT`, `SENTINEL_HOST`, `SENTINEL_DATA_DIR`, `SENTINEL_DB`,
`SENTINEL_ADMIN_PASSWORD`, `SENTINEL_SESSION_TTL_HOURS`.

## Deviations from the original specification

- Report SVG charts are generated by dedicated server-side functions
  (`services/svg.ts`) that mirror the client components' visual language, rather
  than SSR of the React components — avoids coupling the server bundle to React.
- `pnpm package` (single-executable packaging) is documented as an optional
  follow-up, not implemented.
- PDF export is delegated to the browser's print dialog (reports ship print CSS);
  headless-Chromium rendering can be added by installing `playwright-chromium`.
